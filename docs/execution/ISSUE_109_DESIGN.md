# #109 R3 design — opt-in supervised execution custody

Baseline 9209e7414cf9666eaa3071559205527f5b2e6591. Add ao-pilot execution CLI and library, separate from native immutable runtime release. Existing conversation supervisor remains unchanged; do not claim automatic coverage of agent shell commands.

## Invariant

An explicitly enrolled invocation receives unique ID and durable intent before child launch. Persist command argv/cwd, project/session/generation/runtime handle, repository HEAD/tree and dirty-input fingerprint, boot ID, supervisor PID/start identity, child PID/start identity, log paths, times and terminal exit/signal/reason. Use owned persistent configured directory outside /tmp/node_modules; reject git-tracked, symlinked or insecure storage and never make cleanable cache sole evidence. No plaintext environment/credentials; argv credential-like content is rejected or require an explicit secure manifest contract, never log unknown secrets automatically.

CLI: execution run --manifest <explicit-json> --store <durable-dir>; execution inspect <id> --store <dir>. Execution policy is explicit, rerun is never automatic. Standalone invocation creates new ID; optional original invocation reference preserves lineage but does not inherit PASS. Before launch, call injected typed authority validator when supplied; #110 wires scoped authority. Without an authority binding the caller must supply explicit one-invocation local authorization receipt rather than infer from restored conversation. This gate needs exact design specification before implementation.

Separate durable append-only events and per-invocation exclusive custody directory. Intent fsync, stdout/stderr created no-follow/exclusive, then spawn child with cwd and explicit allowlisted environment supplied from manifest. After spawn obtain /proc starttime and boot ID and fsync start identity. If identity write fails, terminate only the just-created child and wait; record unknown/interrupted safely. Child terminal result recorded only after streams close and logs synced; summary must be an explicit bounded artifact contract or raw full terminal log, not parse partial TAP as PASS. Store terminal record by atomic no-overwrite write; no inferred completion for a missing terminal record. Long silence has no timer-triggered kill.

Observer inspect checks terminal record custody/log digests first. Completed terminal record is historical evidence bound to its original identity; it is not automatically evidence for current tree. For unfinished records: boot mismatch means interrupted only if start evidence proves previous boot; same-boot child PID start match means running. Missing child without independently observed exit => unknown/interrupted with reason process_missing, no fabricated exit. Observer uncertainty => unknown/HOLD. Do not kill or relaunch on inspection.

Exclusive lock derived from store+project/session/generation prevents two enrolled authoritative invocations in a lane. Need atomic owner lock, boot+PID-start binding and stale-lock reconciliation that cannot unlink a replacement. Prefer lock-directory owner no automatic stale reclamation: inspect exposes HOLD and explicit authorized resume can create new invocation only after proof original absent and safely bounded atomic reclamation design. No claim this prevents unsupervised writers.

## Validation and rollback

Fake-child tests and real credential-free child fixtures: success/nonzero, signal, long quiet process, truncated terminal, missing log, boot/start mismatch, same-boot PID reuse, observer permission error, duplicate lane, crash between intent/start/terminal, log closure race. Exact invocation ID/tree/log hash asserted, no provider calls and no real host restart. Retention API only archives with durable verified copy; no automatic deletion. Existing installs remain unchanged; additive source rollback preserves records and refuses unsupported schema rather than rewriting them.

Reviewer must settle source authentication/one-invocation grant, locking race model, argv secrets and terminal summary contract before approving design. Delivering only a data schema is insufficient: run/inspect custody needs actual wiring and meaningful process fixtures.

## Revision 1 — exact launch and custody contract

Use a Node barrier helper for explicitly credential-free commands. Helper reports boot/PID/start identity and waits on IPC; no business command runs until parent has fsynced intent/start identity and grant consumption. Helper then spawns business child rather than exec (Node does not portable exec); helper remains a supervised process that owns terminal exit/child start identity and never starts a child without permit. Child group/session teardown and descendant lifetime limits must be recorded; no guarantee for daemonizing commands. Manifest permits fixed minimal PATH/LANG/LC_ALL/TZ only and no arbitrary env. Commands/outputs must be explicitly declared credential-free by enrollment; heuristic key scanning is not a secrecy proof. Dirty fingerprint includes git diff binary against HEAD, cached diff, and named enrolled untracked input bytes; undeclared untracked inputs cause enrollment HOLD.

Lane exclusive directory never automatically reclaimed, including normal terminal evidence failure. After valid completed+logs+summary custody, explicit release under store lock may retire lane receipt; missing/invalid evidence remains HOLD. Recovery policy manifests enroll exact lane and bindings; recoverySweep consults execution observer and consumes typed conversation.restore authority before restore. LIVE or unknown child holds restore; unmatched authority holds. Unenrolled legacy supervisor behavior is explicitly outside this protection.

Completion is completed/exit, separate evidence status established or missing. summary contract names expected terminal marker or artifact and digest; no TAP parsing; log digest and required full marker verified. exit0 without required marker remains evidence_missing, never PASS. Fixed filesystem storage must be owned private persistent directory; explicit /tmp or node_modules paths rejected for actual run, while test-only temporary storage allowed via injected fixture API. No production bypass flag. Existing live supervisor/installations unchanged until separate cutover.

First execution launch is typed execution.run; rerun is typed execution.rerun and carries prior invocation identity. Both require host verifier-backed authority consumed under same ledger lock before permit. #110 consumer is required for enrolled run; no unsigned local authorization bypass.
